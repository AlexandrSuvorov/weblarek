# Проектная работа "Веб-ларек"

Стек: HTML, SCSS, TS, Vite

Структура проекта:

- src/ — исходные файлы проекта
- src/components/ — папка с JS компонентами
- src/components/base/ — папка с базовым кодом

Важные файлы:

- index.html — HTML-файл главной страницы
- src/types/index.ts — файл с типами
- src/main.ts — точка входа приложения
- src/scss/styles.scss — корневой файл стилей
- src/utils/constants.ts — файл с константами
- src/utils/utils.ts — файл с утилитами

# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api

Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные

#### Интерфейс Product

Интерфейс `IProduct` описывает структуру данных для продукта. Он содержит шесть полей:

- `id` - Уникальный идентификатор продукта. Тип данных `string`.
- `description` - Описание характеристик и особенностей. Тип данных `string`.
- `image` - Ссылка на изображение продукта. Тип данных `string`.
- `title` - Краткое название или заголовок. Тип данных `string`.
- `category` - Категория, к которой относится товар. Тип данных `string`.
- `price` - Цена продукта. Тип данных `number` или `null`, если цена не указана.

#### Интерфейс Buyer

Интерфейс `IBuyer` описывает структуру данных покупателя. Он содержит четыре поля:

- `payment` - Тип платежа `TPayment`. Тип `TPayment` содержит в себе строку, описывающую способ оплаты (например: «наличными» или «банковской картой»).
- `email` - Почта покупателя. Тип данных `string`.
- `phone` - Номер телефона покупателя. Тип данных `string`.
- `address` - Адрес покупателя. Тип данных `string`.

#### Интерфейс ICatalogFromApi

Интерфейс `ICatalogFromApi` описывает структуру данных каталога товаров, полученных из API. Он содержит два поля:

- `total` - Общее количество товаров в каталоге. Тип данных `number`.
- `items` - Массив товаров. Тип данных `IProduct[]`.

#### Интерфейс IOrder

Интерфейс `IOrder` описывает структуру данных заказа. Наследуется от `IBuyer` и содержит два поля:

- `total` - Общая сумма заказа. Тип данных `number`.
- `items` - Массив идентификаторов товаров в заказе. Тип данных `string[]`.

#### Интерфейс IOrderResult

Интерфейс `IOrderResult` описывает структуру результата создания заказа. Он содержит два поля:

- `id` - Уникальный идентификатор созданного заказа. Тип данных `string`.
- `total` - Общая сумма заказа. Тип данных `number`.

#### Класс Catalog

Класс `Catalog `отвечает за хранение и управление списком товаров.

Поля класса:

- `items: IProduct[]` - массив всех товаров. Данными является массив интерфейсов `IProduct`.
- `selectedItem: IProduct | null` - товар, выбранный для подробного отображения. `null` начальное значение.

Методы класса:

- `set catalogItems(items: IProduct[])` - сохраняет массив товаров, полученного в параметрах метода. Ожидает на входе массив `IProduct[]`.
- `get catalogItems(): IProduct[]` - возвращает массив всех товаров. Возвращает массив `IProduct[]`.
- `get selectedProduct(id: string): IProduct | null` - возвращает товар по его уникальному идентификатору. Ожидает на входе идентификатор товара с типом данных `string`. Возвращает товар, если найдено совпадение или возвращает `null`, если совпадение не найдено.
- `set selectedProduct(item: IProduct)` - сохраняет товар для подробного отображения. Ожидает на входе интерфейс `IProduct`
- `getSelectedItem(id: string): IProduct | null` - возвращает выбранный товар. Ожидает на входе идентификатор товара с типом данных `string`. Возвращает товар, если найдено совпадение или возвращает `null`, если совпадение не найдено.

#### Класс Cart

Класс отвечает за хранение товаров, добавленных в корзину.

Поля класса:

- `items: IProduct[]` - массив товаров, добавленных в корзину. Данными является массив интерфейсов `IProduct`.

Методы класса:

- `get cartItems(): IProduct[]` - возвращает массив товаров, находящихся в корзине. Возвращает массив `IProduct[]`.
- `addItem(item: IProduct)` - добавляет товар в корзину, который был получен в параметре, в массив корзины. Ожидает на входе интерфейс `IProduct`, добавляемую в корзину.
- `removeItem(item: IProduct)` - удаляет товар из корзины, полученный в параметре из массива корзины. Ожидает на входе интерфейс `IProduct`, удаляемую в корзину.
- `clearCart()` - очищает корзину.
- `get getTotalPrice(): number` - возвращает общую стоимость всех товаров в корзине. Возвращает значение с типом данных `number`.
- `get getItemsCount(): number` - возвращает количество товаров в корзине. Возвращает значение с типом данных `number`.
- `hasItem(id: string): boolean` - проверяет наличие товара в корзине по его id. Ожидает на входе идентификатор товара с типом данных `string`. Возвращает значение с типом данных `boolean`.

#### Класс Buyer

Класс отвечает за хранение и управление данными покупателя.

Поля класса:

- `payment: TPayment` - способ оплаты. Ожидает на входе тип `TPayment`
- `address: string` - адрес покупателя. Тип данных `string`.
- `phone: string` - телефон покупателя. Тип данных `string`.
- `email: string` - email покупателя. Тип данных `string`.

Методы класса:

- `set buyerItem(data: Partial<IBuyer>)` - сохраняет переданные данные покупателя. Позволяет обновлять отдельные поля, не затрагивая остальные.
- `get buyerItem(): IBuyer` - возвращает все данные покупателя. Возвращает интерфейс `IBuyer`
- `clearItem()` - очищает все данные покупателя.
- `validateItem(): Partial<Record<keyof IBuyer, string>>` - выполняет валидацию данных. Возвращает объект с ошибками, где ключ - это поле, а значение - текст ошибки. Если поле валидно, оно отсутствует в объекте.

#### Класс CatalogApi

Класс `CatalogApi` отвечает за взаимодействие с API для получения каталога товаров и отправки заказов.

Поля класса:

- `api: IApi` - экземпляр интерфейса API для выполнения HTTP-запросов.

Методы класса:

- `constructor(api: IApi)` - создаёт экземпляр класса с переданным интерфейсом API. Ожидает на входе интерфейс `IApi`.
- `getCatalogProducts(): Promise<ICatalogFromApi>` - получает список товаров из каталога. Выполняет GET-запрос к `/product`. Возвращает промис с данными каталога типа `ICatalogFromApi`.
- `postOrder(value: IOrder): Promise<IOrderResult>` - отправляет заказ на сервер. Выполняет POST-запрос к `/order` с данными заказа типа `IOrder`. Возвращает промис с результатом заказа типа `IOrderResult`.
